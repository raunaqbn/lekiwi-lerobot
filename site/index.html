01 / System design

One owner. Many observers.

Only the real-time process opens each serial bus. Diagnostics sampling happens inside that owner loop; web and iOS clients receive immutable cached snapshots. A slow browser, camera client, or SSE reconnect stays away from motor I/O.

02 / Reading the panel

“Fault” is not “offline.”

The app separates transport, rail power, per-servo findings, and topology so a dark servo rail does not look like nine unrelated failures.

State What it means First action
HEALTHY The expected servo replied and sampled registers are inside the active bus profile. Continue monitoring; healthy is a recent sample, not a guarantee.
WARNING The motor replied, but temperature, voltage, load, or another reading deserves attention. Reduce load and inspect the named finding.
FAULT A responding device has a critical reading, model mismatch, status bit, or read failure. Stop motion and inspect that motor/cable.
UNPOWERED The USB controller is reachable but no expected servo returns a packet. Check servo rail, shared power, and data chain.
OFFLINE The source endpoint or serial controller is not reachable. Check process, URL, network, and bus owner.
N/A A follower-only ID is absent on a correctly detected six-servo leader. No repair needed; it is outside that profile.
5.3 V versus 10.4 V: both can be correct. The leader uses a 5 V profile; the follower and wheels use the 3S battery rail. The UI never merges them into one unlabeled voltage.
03 / Battery confidence

An estimate, with its uncertainty left on.

The follower estimate uses the median of available follower servo voltage registers in the 3S profile. Median sampling rejects one odd reading; a band communicates chemistry, load sag, sensor resolution, wiring drop, and pack history that voltage alone cannot know.

A

Follower samples only

Leader voltage is never a battery reading. Missing or stale follower telemetry makes the estimate unavailable.

B

Aggregate robustly

Use the median of readable follower voltages instead of trusting one servo.

C

Report a band

Display best estimate plus lower/upper confidence. Never invent runtime without current and capacity history.

Interpretation guide

~12.6 V Near full at rest for a typical 3S Li-ion/LiPo pack.
~11.1 V Nominal region; percentage remains chemistry/load dependent.
~10.5 V Low region; the app intentionally shows a wide estimate band.
<10.0 V Stop and follow the battery manufacturer's limits.

Calibration limits

Motor calibration maps encoder position—not battery state of charge. A better model needs pack-specific resting-voltage tests, known load, current integration, temperature, and cycle aging.

04 / Start here

From clone to signal.

git clone https://github.com/raunaqbn/lekiwi-lerobot.git
cd lekiwi-lerobot
uv sync --locked --extra lekiwi
uv run --extra lekiwi lerobot-lekiwi-diagnostics --demo

No hardware is opened. Inspect the UI, 3D selection, and state vocabulary. 

uv run --extra lekiwi lerobot-lekiwi-diagnostics
# explicit form
uv run --extra lekiwi lerobot-lekiwi-diagnostics \
  --serial-port /dev/serial/by-id/<controller> \
  --follower-url http://lekiwi.local:8091

Auto-detection tries remembered hardware first, then plausible USB serial candidates. 

# Pi
export LEKIWI_FOLLOWER_PORT=/dev/serial/by-id/<follower>
export LEKIWI_DIAGNOSTICS_HOST=0.0.0.0
uv run --extra lekiwi python -m lerobot.robots.lekiwi.lekiwi_host --robot.id=lekiwi

# Leader computer
export LEKIWI_HOST=lekiwi.local
export LEKIWI_LEADER_PORT=/dev/serial/by-id/<leader>
uv run --extra lekiwi python examples/lekiwi/teleoperate.py --no-rerun

Lift the wheels first. The combined dashboard opens on port 8090.

05 / Operator contract

Takeover must look like takeover.

Browser arm mode replaces incoming leader-arm goals with cached dashboard targets. That enables safe hold/jog behavior—but explains why a manual leader appears dead until takeover is released.

Before movement

  • Wheels lifted; arm envelope clear
  • Follower fresh, powered, all nine IDs visible
  • Leader and follower labeled separately
  • Physical cutoff reachable
  • Camera view treated as supplemental

Leader does not move follower

  1. Press Stop and release Follower arm mode.
  2. Confirm the 5555 command stream is changing, not merely connected.
  3. Check follower ownership and telemetry freshness.
  4. Inspect named motor present/goal position and torque.
  5. Then investigate wiring or calibration.

A TCP socket can be established yet idle: connected is not flowing.

06 / Deployment

Cloud at the edge. Motors at the robot.

Pi / systemd

The durable choice: owns serial and cameras, restarts on failure, serves cached telemetry privately.

lekiwi-host@USER.service

Tunnel + Access

Outbound tunnel to an authenticated hostname. Create Access first, deny by default, validate at origin.

Host this guide and static assets. They have no robot USB devices or real-time guarantee.
